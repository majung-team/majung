
# 마중 (Majung)

### 차량 내비게이션과 탑승자를 연결하는 픽업 지원 서비스

마중은 차량 내비게이션의 픽업 장소와 예상 도착 시간, 탑승자의 준비 상태를 하나의 서비스에서 공유하여 운전자와 탑승자 간의 반복적인 연락을 줄이는 것을 목표로 합니다.

운전자는 차량용 애플리케이션에서 픽업 요청을 관리하고, 탑승자는 별도의 앱 설치 없이 모바일 웹에서 차량의 위치와 예상 도착 시간, 픽업 진행 상태를 확인할 수 있습니다.

차량은 **Pleos 기반 Android Automotive OS(AAOS) 애플리케이션**, 휴대전화는 **모바일 웹**을 사용합니다.

## 2. 개발 배경 및 목적

가족이나 지인을 기차역, 학교, 약속 장소 등에서 데리러 가는 과정에서는 운전자의 현재 위치와 도착 예정 시간, 탑승자의 준비 상태를 확인하기 위해 반복적으로 연락하는 경우가 많습니다.

기존의 위치 공유 방식만으로는 차량 내비게이션에 설정된 픽업 장소와 예상 도착 시간, 탑승자의 준비 상태를 함께 확인하기 어려워 추가적인 의사소통이 필요합니다.

**마중은 이러한 정보를 하나의 픽업 과정으로 연결하여 운전자와 탑승자가 동일한 진행 상황을 확인할 수 있도록 지원합니다.**

이를 통해 다음과 같은 효과를 기대합니다.

- 픽업 과정에서 발생하는 반복적인 전화 및 메시지 감소
- 차량 내비게이션 정보를 활용한 도착 예정 시간 공유
- 탑승자의 준비 상태를 차량에서 확인할 수 있는 양방향 소통
- 여러 픽업 요청의 순차적 관리
- 주행 중 조작 최소화 및 픽업 종료 후 위치 공유 중단

반복 연락 감소 등의 실제 효과는 향후 사용자 테스트를 통해 검증할 계획입니다.

## 3. 주요 기능

### 3.1 운전자 중심 픽업 초대

운전자는 차량 내비게이션에서 픽업 장소를 설정한 후 마중에서 해당 장소를 확인하고, 사전에 연결된 탑승자를 선택하여 픽업에 초대할 수 있습니다.

처음 이용하는 탑승자에게는 QR코드 기반 초대 기능을 제공합니다.

**이용 흐름**

1. 차량 내비게이션에서 픽업 장소 설정
2. 마중 차량 앱에서 경로 및 장소 확인
3. 연결된 탑승자 선택 또는 QR 초대 생성
4. 운전자 휴대전화로 초대 링크 전달
5. 탑승자가 모바일 웹에서 초대 수락
6. 픽업 시작 후 차량 위치 및 예상 도착 시간 공유

### 3.2 탑승자 중심 픽업 요청

탑승자도 모바일 웹에서 먼저 픽업을 요청할 수 있습니다.

1. 모바일 웹에서 카카오 로그인
2. 닉네임 또는 마중 ID로 운전자 검색
3. 장소명·주소 검색 또는 지도에서 픽업 지점 선택
4. 운전자에게 픽업 요청 전송
5. 차량에서 요청 확인 및 수락
6. 경로 검증 후 픽업 진행

### 3.3 차량 내비게이션 연동

Pleos NaviHelper를 활용하여 차량 내비게이션의 경로, 목적지, 경유지 및 예상 도착 시간 정보를 확인합니다.

기존 최종 목적지를 유지하면서 픽업 장소를 경유지로 반영하는 흐름을 지원하며, 장소 변경 요청은 차량의 경로 검증을 거쳐 확정합니다.

예상 도착 시간은 차량 SDK에서 제공하는 정보를 활용합니다.

> 서버에서 교통 상황을 별도로 분석하거나 자체 알고리즘으로 예상 도착 시간을 계산하지 않습니다.

### 3.4 실시간 픽업 상태 공유

픽업이 시작되면 권한이 있는 탑승자는 모바일 웹에서 차량의 위치, 예상 도착 시간 및 진행 상태를 확인할 수 있습니다.

탑승자는 자신의 준비 상태를 변경할 수 있으며, 해당 정보는 차량에도 반영됩니다.

웹에서는 SSE(Server-Sent Events)를 통해 상태 변경 신호를 수신한 후 API에서 최신 상태를 다시 조회합니다.

연결이 끊기거나 정보의 유효 시간이 만료된 경우에는 이전 위치 및 예상 도착 시간을 현재 정보처럼 표시하지 않도록 처리합니다.

### 3.5 다중 요청 및 순차 픽업 관리

여러 탑승자에게서 픽업 요청을 받을 수 있으며, 요청은 대기열에서 관리합니다.

실제 픽업은 한 번에 한 건씩 진행합니다.

- 진행 중인 픽업과 대기 중인 요청 분리
- 현재 픽업 종료 후 다음 요청 확인
- 탑승자별 픽업 장소 및 상태 구분
- 대기자에게 다른 픽업의 위치와 예상 시간을 잘못 제공하지 않도록 처리

### 3.6 주행 안전 및 음성 안내

차량의 주행 상태에 따라 사용자 인터페이스를 제한합니다.

시스템 CarUxRestrictions가 적용되는 상황에서는 상세 조작 대신 필요한 정보만 간략하게 표시합니다.

또한 Pleos TTS를 활용하여 사용자가 음성 안내를 활성화한 경우 탑승자 준비 상태와 도착 관련 정보를 음성으로 안내합니다.

### 3.7 연결 복구 및 위치 정보 보호

네트워크 연결이 중단되거나 애플리케이션이 재실행되는 상황을 고려하여 서버 상태를 확인하고, 필요한 경우 사용자의 재개 확인을 거치도록 구성하였습니다.

민감한 로컬 데이터는 암호화하여 저장하며, 픽업 완료 또는 취소 시 위치 정보 공유를 종료합니다.

서버의 픽업 관련 데이터에는 자동 종료 및 보관 기간에 따른 정리 정책을 적용합니다.

## 4. 대표 이용 시나리오

### 가족을 기차역에서 데리러 가는 상황

운전자가 차량 내비게이션의 최종 목적지를 집으로 설정한 상태에서 가족을 태울 역을 픽업 장소로 지정합니다.

차량 앱에서 사전에 연결된 가족을 선택하여 픽업 초대를 보내면, 가족은 휴대전화 웹에서 요청을 수락합니다.

해당 픽업이 시작되면 가족은 차량의 현재 위치와 예상 도착 시간을 확인할 수 있습니다.

가족이 웹에서 '준비 완료'를 선택하면 해당 상태가 차량에 반영되어 운전자가 확인할 수 있습니다.

차량이 역에 도착한 후 운전자가 실제 탑승 완료를 확인하면 픽업이 종료되고 위치 정보 공유도 중단됩니다.

다른 탑승자의 요청이 있다면 대기열에서 별도로 관리하며, 현재 픽업이 종료된 이후 다음 픽업 장소를 확인하여 진행합니다.

대기 중인 탑승자에게는 앞선 픽업의 위치나 예상 도착 시간을 자신의 픽업 정보로 안내하지 않습니다.

## 5. 시스템 아키텍처

![마중 시스템 아키텍처](docs/diagrams/overview.svg)

마중은 차량용 애플리케이션, 백엔드 서버, 모바일 웹으로 구성됩니다.

차량 애플리케이션과 모바일 웹은 HTTPS 기반 API를 통해 서버와 통신합니다.

차량 내비게이션 SDK에서 수신한 위치와 예상 도착 시간 정보는 서버를 통해 해당 픽업에 참여하는 탑승자에게 전달됩니다.

모바일 웹은 SSE로 변경 신호를 수신하고, 실제 상태는 API를 다시 호출하여 조회합니다.

### 서버 배포 구조

백엔드는 내부 Blue-Green 배포 방식을 사용합니다.

1. 현재 서비스 중인 환경을 유지한 상태에서 새 버전 실행
2. 새 환경의 상태 확인
3. 정상 동작 확인 후 Caddy 연결 대상 전환
4. 이전 환경 정리

로그인 세션은 PostgreSQL을 통해 공유하여 배포 환경 전환 시 세션 연속성을 지원합니다.

배포 전환 과정에서 SSE 연결이 끊어질 수 있으며, 웹은 재연결 후 최신 상태를 다시 조회합니다.

> 현재 구성은 애플리케이션 배포 전환을 위한 Blue-Green 구조입니다. VM 및 데이터베이스 장애까지 이중화한 고가용성 인프라는 아닙니다.

[상세 아키텍처 문서](docs/architecture.md)

## 8. 설치 및 실행 방법

### 모바일 웹

1. [마중 웹 서비스](https://majung.cloud/account)에 접속합니다.
2. 카카오 계정으로 로그인합니다.
3. 운전자 또는 탑승자로서 연결 및 픽업 기능을 이용합니다.

웹에 접속하거나 로그인하는 것만으로 차량 위치가 자동 공개되지는 않습니다. 차량 위치는 해당 픽업이 시작된 후 권한이 있는 탑승자에게 제공됩니다.

### 차량용 애플리케이션

1. [GitHub Releases](https://github.com/majung-team/majung-vehicle-app/releases)에서 서명 APK를 내려받습니다.
2. Pleos Connect 공식 에뮬레이터에 설치합니다.
3. 차량 앱에서 QR코드를 확인합니다.
4. 운전자 휴대전화로 QR코드를 열어 계정을 연결합니다.
5. 차량에서 본인 계정을 확인합니다.
6. 내비게이션 경로를 설정하고 픽업 기능을 이용합니다.

탑승자는 별도의 네이티브 애플리케이션을 설치할 필요가 없습니다.

개발 진단용 마중 SDK 확인 애플리케이션은 일반 서비스 이용에 필요하지 않습니다.

[자세한 설치 및 테스트 가이드](docs/team-testing.md)

## 10. 향후 개선 계획

마중은 현재 구현된 핵심 픽업 흐름을 안정화하는 것을 우선 목표로 합니다.

주요 개선 방향은 다음과 같습니다.

1. 실제 휴대전화에서 초대부터 탑승 완료까지 전체 이용 흐름 검증
2. 푸시 알림 및 네트워크 전환 상황에 대한 안정성 검증
3. 주행 중 제한 및 내비게이션 상태 변화에 대한 예외 처리 보완
4. 반복 픽업 편의 기능 개선
5. 탑승자 전용 모바일 애플리케이션 도입 검토
6. 실제 사용자 테스트를 통한 서비스 활용성과 편의성 평가

향후에는 픽업 완료율, 재사용률, 반복 연락 감소 효과 등의 지표를 활용하여 서비스의 개선 효과를 검증할 계획입니다.

현재 실제 사용자 수, 월간 활성 사용자 수(MAU), 재사용률 등의 성과 지표는 측정되지 않았습니다.

## 11. 개인정보 보호 및 서비스 이용 안내

마중은 위치 정보를 활용하는 서비스인 만큼 사용자 권한과 정보 공유 범위를 구분하도록 설계하였습니다.

- 차량 위치는 픽업 시작 후 권한이 있는 탑승자에게 제공
- 대기 중인 탑승자에게 다른 픽업의 위치 및 ETA 비공개
- 픽업 완료 또는 취소 시 위치 공유 종료
- 연결 중단 및 정보 만료 시 오래된 위치 정보 표시 제한
- 차량 첫 이용 시 위치 공유 안내 및 동의 제공
- 데이터 보관 및 정리 정책 적용

개인정보 처리와 관련된 자세한 사항은 다음 문서를 참고할 수 있습니다.

[마중 개인정보 안내](https://majung.cloud/privacy)

## 참고 사항

본 프로젝트는 Pleos Connect 공식 에뮬레이터 및 SDK 기반으로 개발·검증한 차량용 픽업 서비스입니다.

공개 서버와 차량용 APK를 제공하고 있으나, 실제 차량 환경에서의 검증과 앱마켓 입점 심사는 아직 완료되지 않았습니다.

구현 기능, 검증 범위 및 알려진 제한 사항은 개발 문서를 통해 지속적으로 관리합니다.
