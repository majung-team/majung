# 도착 안내와 픽업 조작 보완

기준일: 2026년 11월 5일. 담당: 송승준. 기존 화면 구성을 유지하며 중요한 상태와 다음 행동을 찾기 쉽게 수정했다.

| 문제 | 반영한 내용 |
| --- | --- |
| 입력 중 상태 갱신 누락 | 메시지를 작성해도 도착·취소·종료 안내와 ETA를 갱신한다. 종료된 픽업의 지도는 제거한다. |
| 진입 경로별 도착 안내 차이 | 초대 링크·로그인 화면 모두 상단에 도착 안내와 해당 픽업 보기 동작을 둔다. 입력 중 강제 스크롤은 하지 않는다. |
| 메시지 제한 불일치 | 서버와 같은 50자 제한과 글자 수 표시를 적용했다. |
| 전송 실패 시 초안 유실 | 실패하면 작성 내용을 유지한다. 전송 중 반복 입력을 막고 성공한 뒤에만 비운다. |
| 서버 저장을 차량 수신으로 오해 | 메시지는 서버 저장 완료로 안내한다. 준비 상태는 실제 차량 수신 확인과 구분한다. 운전자의 읽음은 확인하지 않는다. |
| 오래된 ETA 표시 차이 | 두 화면에 같은 최신성 안내를 사용한다. 이전 ETA를 현재 정보로 표시하지 않는다. |
| 지도 실패 시 제안 정보 소실 | 제안 장소·미확정 안내·취소는 남기고 지도 선택 기능만 제한한다. |
| 알림을 눌러 다른 화면으로 이동 | 실제 도착과 3분 전 알림을 구분한다. 해당 픽업의 열린 탭을 찾고 없으면 해당 픽업 경로를 연다. |
| 차량 주요 버튼이 아래로 밀림 | 도착·탑승 완료·다음 픽업 버튼을 스크롤 영역 밖 하단에 고정했다. 주행 제한은 그대로 적용한다. |
| 다른 메뉴에서 새 초대 인지 어려움 | 새 초대 안내와 메뉴 개수를 표시한다. |
| 다음 대기자와 ETA 혼동 | 차량에 다음 대기자 요약을 표시한다. 웹은 내 대기 상태와 앞 픽업의 남은 시간을 분리한다. |
| 지도에서 차량을 다시 찾기 어려움 | 차량과 만날 장소를 다시 화면에 맞추는 버튼을 제공한다. |

## 확인한 범위

- 웹: Node 시험 87개. Chrome 데스크톱·390×844 시험 화면에서 입력 중 도착 표시·초안 유지·가로 넘침 여부 확인.
- 서버: Java 시험 115개, 배포 Python 시험 27개. 암호화 요청 본문·중복 도착 전송 방지·잘못된 키 거절·오래된 위치의 임박 알림 차단 확인.
- 차량: 단위 시험·lint·빌드. 공식 Pleos 2.1에서 긴 내용을 스크롤해도 주요 버튼 전체가 보이며 도착 후 탑승 완료로 바뀌는 기기 시험 1개 통과.
- 알림의 서버 전송과 실제 휴대전화 수신은 다르다. Android·iPhone 홈 화면 웹앱 수신, 실제 시동 종료·재시동은 이번 확인 범위에 포함하지 않았다.
- 기존 ActivityScenario 종료 대기 문제 [차량 #116](https://github.com/majung-team/majung-vehicle-app/issues/116)은 별도로 남아 있다.

## 알림과 접근 권한

이미 알림을 허용한 브라우저는 암호화용 구독 정보를 갱신한다. 새 권한을 자동으로 요청하지 않는다. 알림에는 이름·좌표·초대 토큰을 넣지 않는다. 다른 픽업의 알림까지 끊기지 않도록 한 픽업에서 끌 때 브라우저 전체 구독은 해제하지 않는다.

초대 링크 사용자의 새 탭에는 참여 권한이 없을 수 있다. 이 경우 기존 참여 탭이나 원래 초대 링크로 돌아가도록 안내한다. 알림 URL만으로 위치 조회 권한을 부여하지 않는다. 브라우저 권한·OS 설정·네트워크에 따라 알림이 표시되지 않을 수 있으며 수신을 보장하지 않는다.
