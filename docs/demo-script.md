# 시연 영상 촬영 스크립트

1차 제출용 영상의 촬영 순서다. 기존 영상([시연 영상](pickup-demo.md))은 링크 복사·이름 입력·운전자 승인 시절 흐름이라 현재 제품과 다르다. 새 시연은 연결된 사람 직접 초대 또는 탑승자 요청을 먼저 보여주고, 처음 초대용 QR 공유는 보조 흐름으로 구분한다. 차량·웹 화면 개선과 SSE는 반영됐지만 실제 휴대전화 시험과 새 영상 촬영은 남아 있다. 공식 안내상 영상은 선택 제출이며 일반 시연 영상의 길이 제한은 현재 확인한 안내에 명시되지 않았다([점검표](submission-checklist.md)). 화면의 버튼 문구는 촬영하는 날 앱에서 확인해 맞춘다.

현재 촬영·편집은 승준이 이어간다. 초기 성모 작성 원고는 Git 이력으로 남긴다.

## 준비

- 서버·웹은 운영 주소 `https://majung.cloud`를 쓴다. 촬영 전 [health와 release.json](team-testing.md)의 커밋을 기록한다.
- 차량은 공식 Pleos 에뮬레이터에 `-PpickupApi=https://majung.cloud`로 빌드한 최신 main APK를 설치하고, 차량 최초 등록과 운전자 계정 연결을 끝내 둔다.
- 탑승자는 휴대전화(화면 녹화) 한 대. 시험용 장소와 시험용 계정만 쓴다.
- 촬영 전 가릴 것: 초대 토큰이 보이는 주소창, 실제 집·직장 주소, 카카오 계정 정보, 관리자 키, 서버 내부 정보.
- 영상에 쓴 저장소별 커밋(차량 APK 빌드 커밋 포함)을 영상 설명이나 제출 README에 적는다.

## 장면 순서

| 장면 | 보여줄 것 | 기록할 화면 | 현재 담당 |
| --- | --- | --- | --- |
| 1. 문제 | 픽업 때 "어디야?"·"지금 내려갈까?"가 반복되는 상황 한 줄 자막 | 자막만 | 승준 |
| 2. 픽업 만들기 | 내비게이션에서 만날 장소를 정해 차량 앱에서 픽업 생성 | 차량 | 승준 |
| 3. 초대·연결 | 차량 QR을 운전자 휴대전화로 연 뒤 초대 링크를 탑승자에게 보낸다. 탑승자가 열어 참여하면 이름·가입·승인 없이 연결됨 | 차량 + 휴대전화 | 승준 |
| 4. 이동 중 | 휴대전화에서 지도에 차량 위치와 남은 시간이 보임. 에뮬레이터 주행을 이용 | 휴대전화 | 승준 |
| 5. 준비 상태 | 탑승자가 "준비 완료"를 누르면 차량에 표시되고 휴대전화에 전달 여부가 표시됨 | 휴대전화 + 차량 | 승준 |
| 6. 주행 중 화면 | 차량을 D로 바꾸면 조작 버튼 없이 요약만 보임, P로 돌리면 복귀 | 차량 | 승준 |
| 7. 음성 안내 | 정차 중 음성 안내를 켠 뒤 준비 완료·도착 안내 확인(소리 포함 녹화) | 차량 | 승준 |
| 8. 연결 끊김 | 서버 연결이 끊기거나 유효 시간이 지나면 이전 위치·ETA가 숨겨지고 연결 상태가 표시됨 | 휴대전화 | 승준 |
| 9. 도착 알림 | 도착 약 3분 전 알림이 휴대전화에 도착. 실기기에서 확인된 뒤에만 넣는다 | 휴대전화 | 승준 |
| 10. 장소 제안 | 탑승자가 지도에서 핀으로 다른 장소를 제안, 차량에서 경로를 확인한 뒤 장소가 바뀜. 현재 상태에서 안정적으로 재현될 때만 넣는다 | 휴대전화 + 차량 | 승준 |
| 11. 도착·종료 | 도착 안내, 탑승 확인 후 공유 종료, 종료 뒤 위치가 사라짐 | 차량 + 휴대전화 | 승준 |

9번과 10번은 안정적으로 보여 줄 수 없으면 빼고, 빠진 기능은 기획서의 구현 현황에 "구현됨, 영상 미포함"으로 쓴다. 개발하지 않은 기능은 향후 계획으로 표시한다.

## 표시해야 하는 한계

- 차량은 공식 에뮬레이터이고 실차 주행 영상이 아니다. 자막으로 밝힌다.
- 탑승자의 이동 위치를 계속 추적하지 않는다. 탑승자가 ‘현재 위치’를 직접 골라 요청하면 그 지점을 만날 장소로 전달한다. 지도에 표시하는 차량 위치는 에뮬레이터의 내비게이션 값이다.
- 도착 알림은 웹 푸시이며 iPhone은 홈 화면에 추가한 앱에서만 받을 수 있다.
- 반복 연락이 실제로 줄어드는 효과는 검증하지 않았다. 영상이나 자막에서 효과를 입증한 것처럼 쓰지 않는다.

## 녹화 뒤 점검

- 토큰·실제 주소·계정 정보가 프레임에 나오지 않는지 구간별로 훑는다.
- 소리 있는 장면(7번)이 녹음되었는지 확인한다.
- 11/13 리허설에서 심사용 계정으로 영상 링크를 열 수 있는지 확인한다.

최종 촬영본에는 차량 tag·서버 SHA·웹 SHA를 함께 기록한다. 여러 요청은 한 건씩 진행하며, 대기자에게 현재 다른 픽업의 시간을 자기 ETA처럼 표시하지 않는 것을 확인한다.
