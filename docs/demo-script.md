
# 마중 시연 영상 촬영 계획

**기준일: 2026년 10월 30일**

마중의 주요 기능과 실제 이용 흐름을 보여주기 위한 추가 시연 영상 촬영 계획이다.

기존 10월 29일 영상은 초대 링크 참여부터 탑승 완료까지의 기본 흐름을 담고 있으며, 이번 촬영은 차량 최초 연결, 직접 초대, 실제 휴대전화 이용 및 추가 기능을 보여주는 것을 목표로 한다.

시연 영상은 선택 제출 자료이며, 추가 촬영 여부와 관계없이 기존 영상 및 개발 기록을 유지한다.

---

## 1. 기존 시연 영상

### 기본 픽업 흐름 · 2026.10.29

https://github.com/user-attachments/assets/e181fcc1-599f-47e9-ac96-98135dae2f24

기존 영상에 포함된 기능:

1. 초대 링크를 통한 픽업 참여
2. 차량 SDK 예상 도착 시간 확인
3. 탑승자의 준비 완료 상태 전달
4. 차량에서 수동 도착 처리
5. 탑승 완료 및 위치 공유 종료

해당 영상은 공식 Pleos 에뮬레이터와 로컬 API를 이용한 약 41초 분량의 시연이다.

시험용 픽업은 미리 생성했으며, 웹 화면은 데스크톱 브라우저에서 수집한 단계별 이미지로 구성했다.

차량 최초 연결, 직접 초대, 실제 휴대전화 및 공개 서버의 전체 픽업 흐름까지 검증한 영상은 아니다.

[기존 시연 환경 및 재현 방법](pickup-demo.md)

## 2. 추가 촬영 목표

이번 촬영에서는 실제 사용자가 마중을 이용하는 과정을 중심으로 구성한다.

**핵심 목표**

- 차량에서 픽업 장소 확인 및 요청 생성
- 운전자와 탑승자 연결
- 실제 휴대전화에서 픽업 참여
- 차량 SDK의 위치·ETA 공유
- 탑승자 준비 상태 전달
- 탑승 완료 및 위치 공유 종료

**선택적으로 포함할 기능**

- 주행 제한에 따른 차량 화면 변경
- Pleos TTS 음성 안내
- 네트워크 연결 중단 및 복구
- 도착 임박 푸시 알림
- 탑승자의 장소 변경 제안
- 여러 픽업 요청 및 대기열

선택 기능은 촬영 환경에서 정상적으로 재현되고 결과를 확인한 경우에만 포함한다.

## 3. 촬영 환경 준비

### 서버 및 모바일 웹

운영 주소:

https://majung.cloud

촬영 전 다음 정보를 확인하고 기록한다.

- [서버 health](https://majung.cloud/api/v1/health)
- [웹 배포 버전](https://majung.cloud/release.json)
- 서버 배포 커밋
- 웹 배포 커밋
- 차량 앱 버전 및 빌드 커밋

차량과 모바일 웹이 동일한 운영 서버를 사용하도록 설정한다.

### 차량 앱

- Pleos Connect 공식 에뮬레이터 준비
- 공개 HTTPS API로 빌드한 차량 APK 설치
- 차량 최초 등록 및 운전자 계정 연결
- 내비게이션 경로·목적지 확인
- 위치 공유 안내 및 동의 상태 확인

공개 서버를 대상으로 직접 빌드하는 경우:

```sh
./gradlew :vehicle:assembleDebug -PpickupApi=https://majung.cloud
```

차량 APK는 GitHub 커밋만으로 자동 갱신되지 않으므로 촬영에 사용하는 빌드와 실제 설치 버전을 대조한다.

### 탑승자 환경

- 실제 휴대전화 1대
- 모바일 웹 접속이 가능한 브라우저
- 화면 녹화 기능
- 시험용 계정 및 장소
- 필요한 경우 위치·알림 권한

운전자와 탑승자의 역할을 분리해야 하는 시험에서는 서로 다른 계정을 사용한다.

### 개인정보 보호

촬영 전 다음 정보가 노출되지 않도록 준비한다.

- 초대 링크의 인증 토큰
- 실제 집·직장 주소
- 카카오 계정의 개인정보
- 로그인 쿠키 및 인증 정보
- 서버 관리자 키
- 비공개 내부 설정 정보

## 4. 시연 영상 구성

### 4.1 핵심 장면

가능하면 하나의 픽업 흐름이 시작부터 종료까지 이어지도록 촬영한다.

| 장면 | 촬영 내용 | 화면 |
| --- | --- | --- |
| 1. 서비스 소개 | 픽업 과정에서 반복되는 연락 문제 소개 | 짧은 자막 |
| 2. 픽업 장소 설정 | 내비게이션에서 장소 설정 후 차량 앱에서 확인 | 차량 |
| 3. 초대 및 참여 | QR 초대 생성 → 운전자 휴대전화 공유 → 탑승자 참여 | 차량·휴대전화 |
| 4. 위치·ETA 공유 | 픽업 시작 후 차량 위치와 예상 도착 시간 표시 | 휴대전화 |
| 5. 준비 상태 전달 | 탑승자 준비 완료 → 차량 앱 수신 → 전달 상태 확인 | 휴대전화·차량 |
| 6. 도착 및 탑승 | 도착 처리 → 탑승 확인 → 픽업 완료 | 차량 |
| 7. 위치 공유 종료 | 완료 후 기존 위치와 ETA가 더 이상 표시되지 않는지 확인 | 휴대전화 |

### 장면 1 — 문제 상황

픽업 과정에서 반복적으로 발생하는 연락을 짧은 자막으로 소개한다.

**자막 예시**

> "어디쯤 왔어?"
>
> "지금 내려가면 돼?"

이후 차량과 탑승자가 하나의 픽업 정보를 공유하는 마중의 이용 화면으로 전환한다.

반복 연락 감소 효과를 실제로 측정한 결과처럼 표현하지 않는다.

### 장면 2 — 픽업 장소 설정

1. 차량 내비게이션에서 시험 경로 설정
2. 마중 앱에서 경로 및 장소 확인
3. 픽업 장소 선택
4. 픽업 생성 또는 초대 준비

기존 최종 목적지를 유지하는 흐름이라면 화면에서 해당 관계가 드러나도록 촬영한다.

### 장면 3 — 초대 및 참여

1. 차량에서 QR 초대 생성
2. 운전자 휴대전화로 QR코드 열기
3. 탑승자에게 초대 링크 전달
4. 탑승자가 링크 접속
5. 별도 회원가입 없이 참여 완료

QR 초대와 최초 운전자 계정 연결은 서로 다른 기능이다.

영상에서도 두 QR의 목적이 혼동되지 않도록 구분한다.

### 장면 4 — 위치 및 ETA 공유

1. 차량에서 픽업 시작
2. SDK 위치·ETA 정보 수신
3. 모바일 웹에서 차량 위치 확인
4. 내 픽업 장소까지의 예상 도착 시간 표시

에뮬레이터의 주행 시뮬레이션을 활용할 수 있지만, 실제 도로 주행 결과로 설명하지 않는다.

### 장면 5 — 준비 상태 전달

1. 탑승자가 **준비 완료** 선택
2. 웹에 서버 저장 및 전달 상태 표시
3. 차량 앱에서 준비 완료 상태 확인
4. 웹에서 차량 수신 상태 갱신 확인

차량 앱 수신 여부와 운전자의 실제 확인 여부는 구분한다.

### 장면 6 — 도착 및 탑승 완료

1. 차량의 도착 상태 확인
2. 운전자가 탑승 완료 선택
3. 픽업 종료 처리
4. 모바일 웹에서 종료 상태 확인

수동 도착 기능을 이용했다면 SDK 자동 도착 이벤트를 검증한 것처럼 표현하지 않는다.

### 장면 7 — 위치 공유 종료

픽업 완료 이후 이전 차량 위치와 ETA가 더 이상 표시되지 않는지 확인한다.

완료된 픽업에 다시 접속해도 위치 공유가 재개되지 않는지 확인할 수 있다면 해당 장면을 함께 기록한다.

## 5. 선택 촬영 장면

다음 기능은 안정적으로 재현되는 경우에만 추가한다.

| 기능 | 촬영 조건 | 확인 내용 |
| --- | --- | --- |
| 주행 제한 | 에뮬레이터에서 주행 제한 상태 전환 가능 | 상세 조작 제한 및 요약 화면 |
| 음성 안내 | TTS 출력 및 녹음 가능 | 준비 상태·도착 음성 안내 |
| 연결 중단 | 네트워크 중단 상황 재현 가능 | 오래된 위치·ETA 숨김 |
| 도착 알림 | 실제 휴대전화 푸시 수신 확인 | 도착 약 3분 전 알림 |
| 장소 변경 | 지도 선택 및 SDK 경로 검증 정상 동작 | 제안과 최종 확정 구분 |
| 다중 요청 | 운전자 1명, 탑승자 2명 준비 | 대기열 및 순차 픽업 |

### 주행 제한

에뮬레이터의 시스템 주행 제한 상태를 변경하여 차량 앱의 화면 변화를 확인한다.

- 정차 상태에서 상세 조작 확인
- 주행 제한 상태에서 읽기 전용 요약 확인
- 정차 상태 복귀 후 화면 확인

단순 기어 표시 변경만으로 주행 제한이 적용됐다고 판단하지 않고 실제 CarUxRestrictions 상태와 화면 동작을 확인한다.

### 음성 안내

정차 상태에서 사용자가 음성 안내를 활성화한 뒤 준비 완료 및 도착 안내를 확인한다.

소리가 영상에 정상적으로 녹음된 경우에만 포함한다.

TTS 출력 결과와 실제 차량 스피커·통화 우선순위 검증은 구분한다.

### 연결 중단 및 복구

연결이 끊긴 상태에서 이전 위치와 ETA가 최신 정보처럼 유지되지 않는지 확인한다.

정보가 만료된 후 화면 표시가 변경되는 과정을 촬영한다.

연결 복구 이후에는 서버 상태를 다시 조회하는지 확인한다.

### 도착 임박 알림

실제 휴대전화에서 푸시 알림 수신이 확인된 경우에만 포함한다.

iPhone은 홈 화면에 추가한 웹 앱과 알림 권한 등 지원 조건을 충족한 상태에서 시험한다.

실제 배너가 확인되지 않았다면 해당 장면은 제외한다.

### 장소 변경 제안

1. 탑승자가 지도에서 새로운 장소 선택
2. **제안 보내기** 선택
3. 차량에서 제안 장소 확인
4. SDK 경로 및 ETA 검증
5. 운전자가 확정
6. 웹에 변경된 장소 반영

확정 전까지 기존 픽업 장소가 유지되는지도 함께 확인한다.

### 여러 탑승자의 대기열

운전자 1명과 서로 다른 탑승자 계정 2개로 시험한다.

첫 번째 픽업이 완료되기 전에 두 번째 픽업이 시작되지 않는지 확인한다.

대기자에게 앞선 픽업의 위치나 ETA가 자신의 픽업 정보처럼 표시되지 않아야 한다.

## 6. 시연 영상에 표시할 검증 범위

영상은 실제 촬영한 환경과 검증 범위를 기준으로 설명한다.

### 차량 환경

차량 화면은 **공식 Pleos Connect 에뮬레이터**를 사용한다.

실제 차량 주행 영상으로 표현하지 않는다.

### 위치 및 ETA

위치와 ETA는 차량 내비게이션 SDK에서 수신한 정보다.

서버가 교통 상황을 계산하거나 임의의 ETA를 생성하지 않는다.

탑승자의 위치는 지속적으로 추적하지 않는다. 탑승자가 직접 선택한 장소 또는 현재 위치를 픽업 장소로 전달한다.

### 실제 효과

마중은 반복적인 연락을 줄이는 것을 목표로 하지만, 실제 연락 횟수 감소 효과를 측정한 것은 아니다.

영상 자막에서 효과가 이미 입증된 것처럼 표현하지 않는다.

### 검증하지 않은 기능

촬영에서 제외된 기능은 다음 중 실제 상태에 맞게 구분한다.

- 구현 및 별도 시험 완료
- 구현했으나 실제 기기 검증 필요
- 개발 중
- 향후 계획

영상에 포함되지 않았다는 이유만으로 미구현이라고 판단하지 않으며, 반대로 구현 기록만으로 실기기 검증까지 완료했다고 설명하지 않는다.

## 7. 촬영 후 점검

### 영상 내용

- [ ] 픽업 시작부터 완료까지 흐름이 자연스럽게 이어지는지 확인
- [ ] 차량과 웹 화면의 순서 및 상태가 일치하는지 확인
- [ ] 실제 SDK 정보와 화면 표시가 일치하는지 확인
- [ ] 완료 후 위치 공유 종료가 드러나는지 확인
- [ ] 수동 도착과 자동 도착을 구분했는지 확인

### 개인정보 및 보안

- [ ] 초대 토큰이 포함된 URL 노출 확인
- [ ] 실제 주소 및 좌표 노출 확인
- [ ] 카카오 계정 개인정보 노출 확인
- [ ] 서버 인증 정보 및 관리자 키 노출 확인
- [ ] 불필요한 로그와 개발자 도구 화면 노출 확인

### 녹화 품질

- [ ] 차량 UI와 웹 화면의 글자가 읽히는지 확인
- [ ] 장면 전환과 화면 크기 확인
- [ ] 자막의 기능 설명과 실제 동작 일치 여부 확인
- [ ] 음성 안내 장면이 있다면 소리 녹음 여부 확인
- [ ] 영상 전체 재생 및 파일 오류 확인
