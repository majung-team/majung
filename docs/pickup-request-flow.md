# 픽업 시작 방식과 대기 요청

기존 초대와 탑승자가 먼저 보내는 요청을 함께 사용한다. 2026년 10월 25일 서버 PR #16·웹 PR #15·차량 PR #24가 main에 반영됐다. 접속·설치·시험은 [팀 테스트 안내](team-testing.md)를 따른다.

## 바꾼 이유

운전자가 매번 픽업을 만들고 QR을 찍어 링크를 보내면 번거롭다. 탑승자가 운전자를 찾아 장소와 함께 요청할 수 있도록 했다. 이미 누군가를 픽업 중이어도 두 번째·세 번째 이후 요청을 받아 대기에 넣는다.

## 두 가지 시작 방법

| 방법 | 흐름 |
| --- | --- |
| 연결된 사람에게 직접 초대 | 차량에서 장소 확인 → 연결된 탑승자 선택 → 초대 보내기 → 탑승자가 웹에서 수락 → 대기·차례대로 시작 |
| 처음 연결하는 사람에게 QR 초대 | 차량에서 장소 확인·픽업 생성 → QR을 운전자 휴대전화로 열기 → 탑승자에게 초대 공유 → 참여·차량 승인 |
| 탑승자 요청 | 로그인·운전자 검색 → 현재 위치와 장소 설명 선택 → 마중 요청 → 차량 수락·대기 → 자기 차례에 픽업 시작 |

탑승자가 차량과 연결해둔 적이 없어도 요청할 수 있다. 먼저 별도의 사람 연결 승인을 받도록 요구하지 않는다. 차량에서 마중 요청을 수락하면 이번 픽업을 대기에 넣는다. 기존 사람 연결 목록까지 자동으로 변경하지는 않는다.

지금은 운전자를 검색해 요청한다. 연결 목록에서 바로 다시 요청하는 화면과 장기 연결 링크는 추가 작업이다. 모르는 운전자를 자동 매칭하는 서비스는 아니다.

## 연결된 사람에게 직접 초대

연결된 탑승자에게는 QR을 다시 찍거나 링크를 따로 보낼 필요가 없다. 차량에서 내비 장소를 확인하고 사람을 선택해 초대를 보낸다. 탑승자는 `https://majung.cloud/account`에서 장소를 확인하고 수락·거절한다.

응답 대기는 30분이다. 수락하면 기존 순차 픽업 대기열에 들어가며, 내 픽업이 시작되기 전까지 위치는 공개하지 않는다. 현재 픽업이 끝나도 다음 픽업을 자동 시작하지 않는다. 사람 연결·차량 계정 연결이 해제된 대기 초대는 사용할 수 없다.

2026년 10월 26일 서버 [PR #18](https://github.com/majung-team/majung-backend/pull/18)·웹 [PR #17](https://github.com/majung-team/majung-web/pull/17)·차량 [PR #29](https://github.com/majung-team/majung-vehicle-app/pull/29)로 구현·검증했다. 아직 병합·배포 전이다. 서버 배포 전 추가 컬럼 적용이 필요하다.

탑승자 웹을 닫아둔 동안의 푸시 알림은 아직 없다. 화면을 열어두면 10초마다 초대 상태를 확인한다.

## 운전자와 차량 연결

차량은 관리자 코드로 최초 등록하고 권한을 안전하게 저장한다. 그다음 운전자 본인이 차량 QR을 열어 카카오로 로그인·연결 요청을 보낸다. 차량에서 닉네임·마중 ID를 확인하고 승인해야 연결된다.

차량당 운전자 계정은 한 개다. 같은 운전자가 여러 차량을 연결할 수 있다. 이는 여러 탑승자의 마중 요청을 받는 것과 별개다. 탑승자는 운전자 계정 연결 QR을 스캔하지 않아도 된다.

QR은 5분 만료다. 새 QR은 이전 QR을 무효화한다. 이미 연결된 운전자 계정을 바꾸려면 기존 연결을 해제한다. 사람을 찾는 마중 ID와 차량 등록 권한은 다른 값이다.

## 가입과 사람 찾기

카카오 간편가입 후 마중 서버가 검색용 마중 ID를 발급한다. 닉네임은 따로 정하며 중복될 수 있다. 닉네임이 같으면 마중 ID까지 확인한다. 카카오 회원번호·전화번호·차량 번호·실제 위치를 검색 결과에 공개하지 않는다.

카카오 친구 목록 자동 수집이나 자동 메시지 발송은 포함하지 않는다. 차량 화면에 카카오 비밀번호를 입력하지 않는다.

## 여러 요청 처리

| 상황 | 처리 |
| --- | --- |
| 운전자 응답 전 | 요청 후 30분 만료. 탑승자가 취소 가능 |
| 운전자 수락 | 수락 순서대로 대기에 추가. 대기는 2시간 유지 |
| 기존 픽업 진행 중 새 요청 | 새 요청 접수·수락 가능. 현재 픽업을 바꾸지 않음 |
| 다음 픽업 시작 | 앞선 픽업 종료 후 요청 장소를 내비 경유지로 추가하고 경로 확인 뒤 시작 |
| 취소·거절·만료 | 늦게 누른 수락이나 재전송으로 되살리지 않음 |
| 같은 탑승자의 중복 요청 | 같은 운전자에게 열린 요청이 있으면 새 요청 차단 |
| 요청 과다 | 운전자별 열린 요청 최대 50건 |

현재는 수락 순서대로 한 건씩 진행한다. 자동 경로 최적화, 대기 순서 변경, 승차 정원·하차 구간 관리, 자동 탑승 감지는 포함하지 않는다. 앞사람이 완료됐다고 다음 사람의 위치 공유를 자동으로 시작하지 않는다.

## 대기자에게 보여주는 정보

수락 전에는 **운전자 응답 대기**, 수락 후에는 **수락됨 · 픽업 대기**, 실제 시작 후에는 **내 픽업 진행 중**으로 구분한다.

대기 중에는 내 앞의 요청 수를 보여준다. 현재 진행 중인 픽업의 남은 시간이 새 정보일 때는 아래처럼 구분한다.

> 내 앞에 1건이 있어요.
> 현재 진행 중인 픽업 장소까지 약 5분 남았어요.
> 이 시간은 내 장소 도착 예정 시간이 아니에요.

앞선 탑승자의 이름·장소·마중 ID·좌표는 보내지 않는다. 승하차 시간과 다음 경로를 모르는 상태에서 대기자의 ETA를 계산한 것처럼 표시하지 않는다. 정보가 없거나 오래됐으면 확인할 수 없다고 안내한다.

자기 차례가 시작되면 자기 픽업의 ETA와 준비 상태를 표시한다. 준비 완료·도착·탑승 확인·공유 종료는 기존 픽업 흐름을 사용한다.

## 화면과 알림

차량은 앱이 열린 동안 받은 요청을 조회한다. 새 요청을 확인하고 수락하는 동작에는 기존 CarUxRestrictions를 적용한다. 주행 제한 상태에서는 버튼·확인창을 사용할 수 없다. 속도가 0이라고 임의로 제한을 풀지는 않는다.

앱이 닫혀 있을 때 새 요청을 깨워 알리는 푸시는 아직 없다. 다른 앱 위에 요청 알림을 띄우거나 주행 중 알림에서 바로 수락하는 동작도 확인되지 않았다. 탑승자에게 운전자가 즉시 확인했다고 안내하지 않는다.
