# 마중 화면과 사용 흐름 — 초안 v0.1

작성일: 2026-10-22. 팀 검토를 위한 제안이며, UI나 개인정보 처리 정책이 최종 확정된 문서는 아니다.

## 2026-10-24 변경 안내

이 문서는 초기 화면 초안의 기록이다. 운전자 초대·탑승자 요청·대기 목록의 새 흐름은 [픽업 시작 방식과 대기 요청](pickup-request-flow.md)을 기준으로 한다. 아래 초안이나 영상에 새 기능이 구현됐다고 해석하지 않는다.

## 이번에 만든 것

`design/prototype/`에 차량 화면과 휴대전화 웹을 나란히 놓은 화면 초안을 만들었다.
버튼을 누르면 같은 약속의 상태가 양쪽 화면에 반영된다. 실제 차량 SDK, 지도, 서버는 연결하지 않았다.
기존 Android `probe`의 실제 SDK 시험과 이 화면 시뮬레이션은 별개다.

## 기본 흐름

1. 운전자가 주차 상태에서 차량 내비게이션의 픽업 장소를 확인하고 초대를 준비한다.
2. 운전자 휴대전화에서 차량에 표시된 연결 번호를 입력한다. 휴대전화로 링크를 복사해 전달하는 안이다.
3. 탑승자는 링크로 참여하고 운전자가 알아볼 이름을 입력한다. 참여를 요청해도 위치는 아직 공개하지 않는다.
4. 운전자가 차량에서 참여를 확인하고 위치 공유를 시작한다. 이름 확인은 참가 허용 절차이며 본인 인증을 뜻하지 않는다.
5. 탑승자가 도착 예정 시간과 약속 장소를 보고 준비 상태를 바꾼다. 차량 화면에는 준비 상태를 간단히 표시한다.
6. 내비게이션의 도착 이벤트는 도착 안내로 처리한다. 사용자가 탑승을 확인해 완료하기 전까지 공유를 유지한다.
7. 완료·취소 시 위치 전송과 조회 권한을 종료한다. 웹에도 종료 안내를 보여준다.

연결 번호와 복사 링크는 검토용 예시다. 실제로 차량을 연결하거나 메시지를 발송하지 않는다.
차량에서 휴대전화로 마중 주소를 알리는 방식은 QR 또는 짧은 주소를 비교할 수 있다. 초안에는 번호 입력 흐름만 표현했다.
연결 번호는 운전자 휴대전화 연결용, 초대 링크는 탑승자 참여용으로 구분한다. 같은 권한을 가진 링크로 합치지 않는다.

## 화면별 역할

| 화면 | 반드시 보여줄 정보 | 주요 동작 |
| --- | --- | --- |
| 차량 / 초대 준비 | 내비게이션의 픽업 장소, 공유 전 상태 | 주차 중 초대 생성 |
| 차량 / 휴대전화 연결 | 연결 번호, 참여 확인 전 비공개 안내 | 초대 취소 |
| 운전자 휴대전화 | 차량 연결 여부, 전달할 초대 링크 | 번호 입력, 링크 복사 |
| 탑승자 / 참여 | 참여 목적, 확인 후 위치를 볼 수 있다는 설명 | 알아볼 이름 입력, 참여 요청 |
| 차량 / 참여 확인 | 참여자가 입력한 이름, 공유 범위 | 주차 중 확인·공유 시작 또는 취소 |
| 차량 / 이동 중 | 준비 상태, 확정 장소, 연결 상태 | 허용 범위 안의 짧은 표시만 검토 |
| 탑승자 / 대기 | 위치·예상 시간·갱신 상태·확정 장소 | 준비 중·준비 완료, 장소 변경 제안 |
| 차량 / 장소 변경 | 제안 장소와 현재 확정 장소의 구분 | 주차 후 변경 요청 또는 기존 장소 유지 |
| 도착 / 종료 | 도착 안내와 탑승 완료의 구분 | 주차 후 완료·공유 종료 |

차량 화면은 실제 Pleos의 창 배치를 이해하기 위한 모형이다. 내비게이션과 나란히 표시하는 안이며 주행 중 UI 허용을 확인한 결과물은 아니다.
주행 여부는 실제 구현에서 `CarUxRestrictions`와 플랫폼 상태로 결정한다. 이 초안의 ‘주차 중 / 주행 중’은 검토자가 바꾸는 시뮬레이션 설정이다.

## 예외 상황

### 장소 변경

제안 중에는 기존 약속 장소를 유지한다. 운전자 확인 뒤 경로를 요청하되 요청을 보냈다는 이유만으로 장소를 바꾸지 않는다.
새 목적지와 경로 정보의 일치를 확인한 뒤 확정 장소의 버전을 올린다. 실패하면 기존 장소를 보존한다.
반영 중에는 이전 예상 시간을 숨기고, 실패 뒤에도 기존 경로가 유효한지 다시 확인하기 전에는 시간을 다시 표시하지 않는다.
초안의 ‘내비게이션 응답 재현’ 버튼은 성공·실패 상황을 직접 살펴보기 위한 개발 도구다.

### 차량 연결 끊김과 준비 상태

위치가 갱신되지 않으면 지도 위의 차량과 예상 시간을 현재 정보처럼 보여주지 않는다.
탑승자가 새 준비 상태를 선택해도 차량의 수신 확인이 없으면 ‘차량 반영 대기’로 표시한다.
실제 서버에서는 상태 저장과 차량 전달 확인을 구분해야 한다. 브라우저 초안에는 재연결과 상태 동기화를 한 장면으로 표현했다.

### 종료와 만료

완료·취소는 실수로 누르지 않도록 한 번 확인한다. 도착 이벤트가 자동으로 완료를 실행하지 않는다.
종료된 픽업은 탑승자 화면에서 위치·예상 시간·약속 장소를 더 이상 조회할 수 없게 한다.
사용하지 않은 초대가 만료되면 참여를 막는다. 만료 시간과 최대 공유 시간은 아직 팀에서 정하지 않았다.

## 지금 결정해야 할 것

- 운전자 휴대전화 연결에 쓸 진입 방식: QR, 짧은 주소와 번호, 다른 방식 중 선택.
- 차량 화면에서 시작한 약속을 휴대전화에 연결하는 인증 방식. 연결 번호만 입력하는 시늉과 실제 권한 부여를 구분한다.
- 최초 범위에 장소 변경 제안까지 포함할지. 좌표 경로 요청은 에뮬레이터의 한 예제에서 확인했으나 다양한 장소 시험이 남았다.
- 주행 중 허용할 정보 표시. 현재 화면이 심사에 적합하다고 확정하지 않는다.
- 링크 만료·최대 공유 시간·다시 초대할 때 기존 링크를 철회하는 기준.
- 실제 지도·장소 검색 서비스의 범위와 이용 조건.

## 확인한 범위

- 브라우저에서 초대 연결 → 참여 요청 → 운전자 확인 → 준비 상태 변경 → 장소 변경 실패·성공 → 도착 → 종료를 직접 실행했다.
- 주행 중 장소 변경 승인 버튼이 비활성화되고, 연결 끊김에서 위치·ETA가 숨겨지는 것을 확인했다.
- 상태 전이·공개 범위 관련 Node 테스트 8개가 통과했다. 이는 초안의 상태 모델 시험이며 실제 서버의 접근 통제가 검증됐다는 뜻은 아니다.
- 실제 iPhone·차량 화면, 웹 푸시, 서버 동기화, QR 인식, 실제 지도는 검증하지 않았다.

## 다음 구현 단위

차량 앱과 탑승자 웹을 한꺼번에 넓게 만들기보다 ‘픽업 한 건 생성 → 참여 확인 → 준비 상태 전달 → 공유 종료’부터 서버로 연결한다.
실제 차량 위치를 외부에 공유하기 전에는 운전자·탑승자의 권한, 연결 번호와 초대 토큰의 수명, 종료 후 접근 차단을 먼저 구현한다.
