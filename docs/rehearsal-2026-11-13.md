모든 앱의 개별 검사가 통과한 것을 세 기기 사이 운영 종단 간 통과로 합산하지 않는다.

SDK 최초 병행 실행은 ActivityScenario 종료 단계에서 실패했으며, 단독 재실행 3개 통과 결과와 구분한다.

## 실패·제한 및 보완점

1. 최초 `VehicleAccountTest` 실패: 전체 2건을 운전자 요약에 기대하던 검사와 항상 보이지 않는 이전 버튼 기대가 현재 화면과 달랐다. 대기 1건·진행 중 1건을 화면에 보이는 행으로 구분하도록 수정해 통과.
2. 최초 `PickupActionDockTest` 실패: 위치 권한 창·공유 서비스와 섞여 상태 전환 검사가 불안정했다. 복구 확인 대기 상태로 분리하고 로컬 HTTP의 도착 응답으로 전환해 완료 버튼의 노출·활성화를 확인. 실제 완료 버튼 고장으로 판정하지 않음.
3. 최초 위치 권한 검사 실패: 등록되지 않은 기본 API 의존성을 제거했다. 별도 ACTIVE 응답·권한 거절 상태에서 서비스 시작 시도 후 실행 안 됨·위치 쓰기 0건·전송 순번 유지 확인. 실제 권한 창 조작 시험은 별개.
4. 운영 웹에서 취소 기록이 계속 같은 목록에 쌓임. 현재 요청과 지난 기록을 나누고 지난 기록은 접거나 제한하는 개선 권장.
5. 장소를 고른 뒤 `만날 장소 설명`을 고치면 요청 요약에 수정한 문구만 표시됨. 장소명과 탑승 메모를 분리해 수신자가 장소를 바로 식별하도록 보완 권장.

## 운영 양방향 추가 확인 · 11월 14일

- 기존 서명 앱 0.2.34-preview / versionCode 36과 majung.cloud를 사용했다. 실차·실물 iPhone 없이 공식 Pleos 에뮬레이터와 Chrome에서 진행했다.
- 차량 QR을 이미지에서 읽어 초대 전달 화면과 참여 화면을 열었다. 물리 카메라 촬영으로 기록하지 않는다.
- 첫 픽업: 실제 SDK의 약 1분 ETA → 웹 메시지 전송 → 차량 메시지 알림/본문 확인 → 장소 제안 수신/확인 대기 → 웹에서 제안 철회 → 준비 완료 전달 확인 → 차량 수동 도착 → 웹 도착 배너 확인.
- 차량 프로세스를 종료하고 재실행한 뒤, 명시한 동일 ARRIVED 픽업만 완료하는 계측 검사 1개 통과. 저장된 접근 정보 제거 확인, 웹에서 완료·위치/ETA 제거 확인.
- 두 번째 픽업: 브라우저 확인 메시지를 완료 단계의 신호로 사용해 전체 계측 검사 1개 통과(69.85초). 첫 실행에서 앱 내부 완료 신호 파일에 접근할 수 없어 완료 대기가 막힌 점을 검사 방법에서 보완했다. 이 파일 대기 문제를 제품 오류로 기록하지 않는다.
- 완료된 웹에 잘못 나타나던 ‘원래 열어둔 화면’ 안내는 [웹 PR 119](https://github.com/majung-team/majung-web/pull/119)로 수정·운영 배포 확인. 완료·취소·만료와 권한 없는 새 탭 4개 회귀 추가, 전체 111개 통과.
- 차량 ACTIVE 화면에 이전 초대 생성 안내가 남는 현상은 [차량 PR 138](https://github.com/majung-team/majung-vehicle-app/pull/138)에서 상태 전환 시 정리한다. 복구·저장 오류 메시지는 유지하며 HTTP 회귀로 확인.
- 이번에 만든 운영 시험 픽업 두 개는 모두 완료했다. 기존 진행 중 픽업을 취소하는 시험은 하지 않았다.

## 발표 순서

1. 첫 화면과 카카오 로그인·닉네임 설정 소개. 실제 인증 촬영이 없으면 이미 로그인된 화면이라고 명시.
2. 차량 QR→휴대전화 연결 요청→차량의 본인 확인 흐름 소개. 카메라 촬영과 링크 입력 시연을 구분.
3. 웹 또는 iOS에서 장소 검색→요청→차량 수락→ETA 확인. 같은 운영 픽업을 연결한 리허설이 끝난 뒤 본 시연에 사용.
4. 탑승 준비→짧은 메시지→장소 제안. 내비 위 알림·수락·새 경로 반영을 보여줄 때는 실제 차량 SDK 확인본만 사용.
5. 도착→탑승 완료→공유 종료. 완료 화면의 장소·차량 요약 확인.
6. 취소→재요청을 짧게 추가. 운영 웹에서 이번 점검으로 재현한 흐름.

라이브 종단 간 리허설 전에는 단계별 검사 화면을 하나의 실시간 양방향 시연처럼 편집하지 않는다. 기존 11월 10일 차량·웹 시연 영상은 당시 환경의 기록으로 구분한다.

## 기능 지원 안내

- 카카오 로그인 유지, Apple 로그인 추가 취소. App Store 출시·체험하기 버튼 추가 진행하지 않음.
- iOS 네이티브 APNs 원격 푸시와 HTTPS 유니버설 링크는 별도 개발자 권한·서명·서버 설정 및 실기기 검증 필요. 현재 검증 완료 기능으로 소개하지 않음.
- 직접 누르는 `majung://` 앱 열기와 앱 내 로컬 도착 알림은 위 기능과 구분.
- 웹 푸시는 네이티브 APNs 인증서 설정과 별개. iPhone 웹 푸시의 홈 화면 추가·알림 권한 조건을 따로 설명하며 유료 Apple 계정이 반드시 필요한 기능으로 묶지 않음.
