
# 남은 작업 및 향후 계획

**갱신일: 2026년 11월 12일**

마중의 현재 개발 상태와 추가 검증이 필요한 항목, 향후 개선 계획을 정리한 문서다.

차량 앱, 모바일 웹, 백엔드의 주요 기능은 구현했으며 공식 Pleos 에뮬레이터와 시험 서버에서 핵심 동작을 확인했다.

현재는 경유지 좌표와 복구·ETA 등 핵심 흐름의 안정성을 먼저 확인한다. 제출 자료 정리는 그 결과를 반영해 진행한다. 실제 휴대전화 통합 테스트와 실차 검증은 자동 시험과 구분한다.

완료되지 않은 시험은 구현 여부와 관계없이 미검증 상태로 유지한다.

## 1. 현재 우선 작업

### 핵심 안정성 확인

- 기존 경유지 좌표 복원·재선택, Android 세션 복구 및 재실행 시 미검증 차량 위치 즉시 삭제: 단위 60개·기기 시험 6개 통과 ([차량 #87](https://github.com/majung-team/majung-vehicle-app/pull/87) · [#92](https://github.com/majung-team/majung-vehicle-app/pull/92))
- 서버 HTTP 응답과 웹 ETA 계산: 5개 시나리오 통과, CI에 배포 웹 버전 고정 검사 추가 ([서버 #51](https://github.com/majung-team/majung-backend/pull/51))
- 동시성·권한·SSE·푸시 구독·장소 확정 및 도착·해제 시 미확정 제안·진행 중 픽업 정리: 서버 회귀 시험·웹 테스트 76개 통과 ([서버 #64](https://github.com/majung-team/majung-backend/pull/64) · [웹 #79](https://github.com/majung-team/majung-web/pull/79))
- 일일 백업·주간 복원·매분 운영 점검·외부 HTTPS 감지 및 WIF 예약 실행 복구 적용 ([서버 #62](https://github.com/majung-team/majung-backend/pull/62))
- 비공개 외부 백업·다운로드 검증·외부 복사본 실제 복원 통과. 세션 인증·계정·픽업 HTTP 조회·로그아웃 후 차단 확인
- API 5xx·p95 상한·DB 풀·OAuth 결과 점검 운영 적용, 외부 백업 30시간 누락 감지
- 안내 취소·백그라운드 경로 변경·공유 복구 및 SDK 타임아웃·단절 시 경로 변경 상태 정리: 공식 에뮬레이터 재시험 통과 ([차량 #89](https://github.com/majung-team/majung-vehicle-app/pull/89) · [#92](https://github.com/majung-team/majung-vehicle-app/pull/92))
- 남은 현장 확인: 실제 시동 종료, 휴대전화 푸시 수신·LTE 전환, 경보 이메일 실제 수신

[검증 범위와 제한](https://github.com/majung-team/majung-backend/blob/main/docs/stability-verification.md)

### 최근 픽업 검증

Chrome 모바일 크기와 데스크톱에서 초대 재시도·참여·재접속·취소를 확인했다. Pleos에서 장소 변경, 앱 강제 종료 후 위치·도착 시간 공유 재개, 두 번째 대기 픽업을 확인했다. 남은 검증은 최신 버전의 실제 iPhone 픽업 전체 흐름과 실차 시동 종료·재시동이다. [11월 9일 검증 기록](development-status.md#11월-9일--첫-초대와-픽업-복구)

### 기존 사용성 보완

입력 중 도착·취소 표시, 메시지 초안 보존·50자 제한, 알림의 픽업별 이동, 지도 복귀, 차량 하단 완료 버튼은 반영했다. [변경 내용과 시험 범위](critical-feedback-2026-11-05.md)를 기준으로 확인한다. 실제 휴대전화의 도착 푸시 수신과 실차 시험은 남아 있다.

## 2. 현재까지 확인한 범위

### 차량 앱 및 SDK

- Pleos 공식 에뮬레이터에서 주요 픽업 흐름 검증
- 차량 SDK 기반 경로 및 ETA 확인
- 장소 변경 제안과 경로 검증
- 순차 픽업 처리
- 연결 복구 및 픽업 종료 관련 시험

### 모바일 웹

실제 iPhone Chrome에서 다음 항목을 확인했다.

- 공개 HTTPS 서비스 접속
- 카카오 로그인
- 탭 및 화면 이동
- 운전자 검색
- 웹 재접속

입력 화면 확대와 빈 목록의 페이지 버튼 표시 문제를 개선하고 배포했다.

[웹 PR #73](https://github.com/majung-team/majung-web/pull/73)

현재 실제 iPhone에서 확인한 계정은 운전자 계정과 동일하다.

서로 다른 탑승자 계정으로 진행하는 요청·수락·위치 공유·탑승 완료의 전체 과정은 별도 검증이 필요하다.

### 백엔드 및 운영

- 공개 HTTPS 서버 운영
- PostgreSQL 기반 데이터 및 공유 세션 관리
- Blue-Green 배포 구조 적용
- 서버 전환 및 배포 자동화 테스트
- SSE 재연결과 최신 상태 재조회 구조 반영

현재 Blue-Green은 애플리케이션 배포 전환을 위한 구조이며, VM이나 데이터베이스 자체를 이중화한 구성은 아니다.

[운영 버전 및 배포 검증](runtime-2026-10-29.md)

## 3. 추가 검증이 필요한 항목

### 3.1 실제 휴대전화 통합 테스트

**우선순위: 높음**

서로 다른 운전자·탑승자 계정을 사용하여 전체 픽업 흐름을 확인해야 한다.

- 탑승자 픽업 요청
- 운전자 요청 수락
- 내비게이션 경로 확인 및 픽업 시작
- 차량 위치 및 예상 도착 시간 공유
- 탑승자 준비 상태 변경
- 장소 변경 제안 및 확정
- 탑승 완료 후 위치 공유 종료
- 여러 탑승자의 순차 픽업

현재 일부 화면과 로그인 기능은 실제 휴대전화에서 확인했지만, 전체 통합 테스트를 완료한 상태는 아니다.

### 3.2 네트워크·위치·알림

**우선순위: 높음**

- 실제 GPS 위치 및 권한 처리
- 위치 권한 거절 시 동작
- LTE·Wi-Fi 전환
- 연결 중단 및 재접속
- 정보 유효 시간 만료 처리
- 실제 휴대전화의 푸시 알림 배너 수신
- iPhone 홈 화면 웹 앱의 알림 동작

에뮬레이터 또는 시험 서버에서 확인한 결과를 실제 휴대전화 검증 결과와 구분한다.

### 3.3 차량 SDK 및 실차 검증

**우선순위: 높음**

- 내비게이션 도착 이벤트 재현
- 내비게이션 안내 취소 후 상태 정리
- 장시간 실행 및 백그라운드 복구
- 실제 차량 환경에서의 경로·ETA 확인
- 주행 제한 정책 적용
- 실제 스피커를 통한 음성 안내
- 통화 및 다른 음성 안내와의 우선순위

실차 검증은 현재까지 수행하지 않았다.

## 4. 알려진 이슈

### 내비게이션 취소 후 안내 상태 유지

[차량 이슈 #56](https://github.com/majung-team/majung-vehicle-app/issues/56)

10/31 공식 에뮬레이터·SDK 3.0.5 재시험에서 두 번 모두 취소 콜백과 안내 중지를 확인했다. 백그라운드 경로 변경·취소 후 위치 숨김 12초·새 안내·재연결 후 공유 복구 시험도 통과해 이슈를 종료했다. 과거 실패 원인은 확정하지 않았으며 재발 시 해당 환경과 함께 재개한다.

[재시험 근거](https://github.com/majung-team/majung-vehicle-app/tree/main/evidence/2026-10-31-sdk-cancel)

### SDK 경유지 원본 좌표 응답

[차량 이슈 #13](https://github.com/majung-team/majung-vehicle-app/issues/13)

SDK에서 경유지 원본 좌표가 `0`으로 반환되는 현상이 확인됐다.

앱의 경유지 식별자 대조와 경로·ETA·재연결 관련 시험은 통과했다.

다만 SDK 제공 측의 원본 응답은 공식 문의 후 답변을 기다리고 있다.

관련 시험 통과와 SDK 원본 응답 문제의 해결 여부는 별도로 관리한다.

## 5. 후속 개발 계획

### 서비스 이용 지표

현재 익명 이용 지표 수집 기능은 구현되지 않았다.

향후 서비스 검증을 위해 다음 지표를 검토한다.

- 픽업 요청 및 완료 건수
- 픽업 완료율
- 서비스 재사용률
- 픽업 요청부터 시작까지의 소요 시간
- 반복 연락 감소 효과

실제 측정되지 않은 사용자 수나 서비스 효과를 성과로 기재하지 않는다.

### 운영 안정성

- 정기적인 PostgreSQL 백업 복원 점검
- 서버 장애 및 복구 절차 보완
- 장시간 실행 중 연결 안정성 확인
- 배포 실패 및 복구 기록 관리

### 향후 기능 확장

핵심 픽업 흐름이 안정화된 이후 다음 기능을 검토한다.

- 반복 픽업 편의 기능
- 탑승자 전용 모바일 애플리케이션
- 이용 흐름 및 알림 편의성 개선

새로운 기능 확장보다 현재 구현한 픽업 흐름의 안정성을 우선한다.

## 6. 현재 개발 범위에서 제외한 항목

다음 항목은 현재 필수 구현 또는 검증 범위에 포함하지 않는다.

**VIN 기반 차량 인증**

차대번호(VIN) 연동은 현재 필수 기능이 아니다.

마중의 차량 등록 ID는 서비스 내 차량 연결을 위한 식별자이며, 실제 차대번호나 차량 소유권 인증을 의미하지 않는다.

**사용자 조사**

사용자 설문 및 인터뷰는 이번 제출 범위에 포함하지 않았다.

향후 서비스 개선 효과를 검증하는 단계에서 별도로 검토할 수 있다.

**실차 배포 및 앱마켓 입점**

공식 Pleos 에뮬레이터 기반 개발·검증과 실제 차량 배포 및 앱마켓 입점은 별개의 단계다.

현재 실차 검증 및 앱마켓 입점 심사는 진행하지 않았다.

## 7. 다음 단계

현재 개발 단계에서 우선순위는 다음과 같다.

1. **제출 자료 정리:** README, Wiki, 시연 영상, APK 및 개발 근거 정합성 확인
2. **통합 검증:** 서로 다른 실제 휴대전화 계정을 이용한 전체 픽업 테스트
3. **안정성 검증:** 네트워크 전환, 알림, SDK 상태 및 장시간 실행 확인
4. **실차 검증:** 실제 차량에서 내비게이션 연동 및 주행 제한 동작 확인
5. **기능 개선:** 실제 이용 결과를 바탕으로 편의 기능과 운영 안정성 보완

제출 준비 과정에서는 기존 검증 결과를 유지하고, 추가 테스트가 수행되면 결과와 환경을 별도로 기록한다.
