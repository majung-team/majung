- 서버 PR #21: 정상 차량 정보가 30분 끊기거나 최초 도착 후 30분이면 EXPIRED. 최대 12시간, 종료 후 7일 보관. 최신 자동 연결·푸시 코드를 합친 시험 74건 중 73건 통과, 기존 수동 시험 1건 제외.

차량은 새 APK를 설치해야 바뀐다. 서버·웹은 main 병합 후 Actions로 각각 배포된다. 실제 배포 완료는 아래 기록과 공개 health·release.json으로 대조한다.

## 서버·웹 확인

자동 배포가 모두 성공했고 공개 응답에서 서버 `33342e3`, 웹 `6e7fb09`를 확인했다. 차량 main은 `9307a76`이며 새 APK 설치가 필요하다. 이 값은 이번 확인 시점의 기록이다.

도착 알림용 `arrival_push` 테이블과 실행 권한, 배포 스크립트의 웹 파일 목록을 적용했다. VAPID 키는 서버에서 생성해 root 전용 환경 파일에 저장했다. 브라우저에는 공개 키만 전달한다.

운영 Chrome의 가상 시험 픽업에서 권한 허용·구독·해제를 확인했다. 시험 ETA 400초·120초를 전달했고 시험 픽업은 취소, 시험 차량 권한은 철회했다. OS 배너가 표시되는 것을 직접 확인하지 못했으므로 실제 알림 수신 완료로 기록하지 않는다. 실제 휴대전화 수신도 남아 있다.

자동 종료 배포에 필요한 세 열은 확인했고, 운영 DB를 백업한 뒤 기존 ARRIVED·ACTIVE 행의 빈 활동 시각을 보완했다. 개인 정보·권한 원문은 이 문서에 넣지 않는다.

## 동료와 시험하기

각자 PC에 공식 Pleos 에뮬레이터와 새 차량 APK를 설치한다. APK는 `-PpickupApi=https://majung.cloud`로 빌드한다. 차량 권한 파일은 공유하지 않고 각자 등록한다.

`http://127.0.0.1:8088/`은 각자 에뮬레이터 조작용 콘솔이다. 차량 앱과 휴대전화는 공용 `https://majung.cloud`를 사용한다. 같은 Wi-Fi가 아니어도 된다. [차량 주행 시험](https://github.com/majung-team/majung-vehicle-app/blob/main/docs/driving-summary.md)을 따른다.

도착 알림은 진행 중인 픽업에서 ‘도착 3분 전 알림’을 허용해 시험한다. iPhone은 홈 화면에 추가한 앱에서 `/account`로 로그인해 확인한다. 이 알림은 새 마중 요청·초대 알림이 아니다.

## 지도와 SSE

HANMAP의 카카오맵 설정은 OFF로 확인했다. 무료 쿼터는 자동으로 옮겨지지 않아 [마중으로 이관 요청](https://devtalk.kakao.com/t/topic/152375)을 게시했다. 처리 전에는 마중 지도를 유료로 활성화하거나 HANMAP 키를 재사용하지 않는다. 지도 브랜치 main 반영·전용 키·CSP·실제 지도 표시는 이관 후 진행한다.

SSE는 아직 사용하지 않는다. [ETA 갱신과 SSE 검토](https://github.com/majung-team/majung-web/blob/main/docs/eta-updates.md)에 쿠키·Bearer 인증, 종료·재연결, 조회 복귀 조건을 정리했다. 화면 카운트다운과 내비 SDK의 교통 상황 재계산은 별개다. 실차 정체·우회 상황은 미확인이다.
