## 블루·그린 실제 전환

1. 마중 PostgreSQL 백업 후 세션 테이블 두 개와 앱 계정 권한을 추가했다. 기존 픽업 테이블은 삭제하지 않았다.
2. 공유 세션 코드 반영 후 기존 8080 서버에서 blue 8081로 옮겼다.
3. [Actions 수동 실행](https://github.com/majung-team/majung-backend/actions/runs/40826338867)으로 같은 커밋을 green 8082에 배포했다.
4. 후보의 DB·세션 테이블·커밋·슬롯 확인 후 Caddy를 전환하고 이전 서버를 종료했다.
5. [서버 #46 자동 배포](https://github.com/majung-team/majung-backend/actions/runs/40827888795)에서 새 커밋으로 green→blue 전환도 성공했다.
6. 활성 슬롯 파일·배포 상태·실행 서비스·재부팅 시 시작 서비스가 같은 슬롯인지 확인했다.

첫 전환의 공개 health 70회, Actions 전환 구간 159회에서 HTTP 실패는 없었다.
각 전환 전 발급한 익명 세션·CSRF로 전환 후 로그아웃 204를 확인했다.
실제 로그인은 같은 시험 DB를 사용하는 두 HTTP 서버에서 사용자·CSRF 공유와 로그아웃 동기화를 검증했다.
운영 카카오 계정으로 배포 전후를 반복 로그인한 결과로 바꾸어 적지 않는다.

서버 테스트 총 100건 중 99건 통과, 선택 실행용 1건 제외. 배포 자동 시험은 13건 통과했다.
후보 실패·공개 확인 실패·Caddy reload 실패의 복구는 자동 시험이며, 운영 장애를 일부러 만든 결과는 아니다.
한 VM·DB를 사용하는 구성이므로 장비나 DB 장애의 이중화와는 다르다.
SSE는 서버 전환 때 재접속할 수 있고 클라이언트가 현재 상태를 다시 읽는다.

## 차량·웹에서 달라진 부분

- 차량 첫 실행의 위치 공유 안내·동의 저장·철회, 동의 전 공유 차단 반영.
- 탑승자의 장소 제안을 현재 장소와 별도 카드로 표시. SDK에서 경로·ETA를 검증한 뒤 확정 가능.
- 공식 SDK+로컬 API에서 최종 목적지·다른 경유지를 유지하고 제안 장소 검증·재연결·장소 버전 2 반영 확인.
- 내용이 없는 차량 섹션은 숨겨 빈 흰색 막대 제거.
- 같은 탭에서 뒤로가기 후 초대 링크를 다시 열 때 기존 참여 복구. 다른 픽업·종료·철회는 계속 차단.
- [개인정보 안내](https://majung.cloud/privacy)의 위치 공유·보관·운영자 문의와 모바일 크기 화면 확인.
