## 먼저 정해야 하는 것

메일 제목 `[차량용 앱 개발 공모전] 팀명(개인은 성명)_대표자명`과 APK 파일명 `팀명_앱이름_release.apk`에 쓰이므로 다른 작업보다 앞서 정한다.

- [ ] 팀명
- [ ] 대표자
- [ ] 참가 부문(대학생 / 일반). 시상과 심사가 부문별로 나뉜다. 부문 기준은 「참가 규정」 페이지에서 확인한다
- [ ] 제출할 저장소 구성: 소개와 시연은 `majung`, 코드와 APK는 `majung-vehicle-app`, 서버와 웹은 각 저장소. 심사용 계정은 필요한 저장소에 모두 초대해야 한다

## 형식 요건

- 접수 이메일: appdevchallenge@hyundai-partners.com. 대표자가 팀원 전원을 참조(CC)에 넣는다.
- 수정 제출은 마감 전에 처음 보낸 주소로 다시 보낸다. 제목 앞에 `[수정제출]`을 붙이고 모든 자료와 서명한 동의서를 다시 첨부한다. 마감 전 마지막 제출본이 최종본이다.
- APK는 저장소의 `apk/` 폴더에 실행 가능한 release 버전으로 올린다. 용량이 크면 GitHub Releases에 올리고 그 페이지 주소를 제출한다.
- 비공개 저장소는 심사용 GitHub 계정을 Collaborator로 초대한다. Collaborator에게는 쓰기 권한도 주어진다. 초대 전에 권한을 확인하고, 마감 전에 심사용 계정으로 접근되는지 확인한다.
- 제출 저장소의 README에는 앱 이름과 한 줄 소개, 실행 방법, 테스트 환경과 필요한 설정, APK 위치 또는 Release 링크가 있어야 한다.

## 심사 항목과 우리 자료

세부 배점은 공개되지 않는다. 네 항목이 모두 필수이고 개발 산출물은 가산점이다.

| 항목 | 기획서에 쓸 근거 | 비어 있는 것 |
| --- | --- | --- |
| 차량특화성 | 차량 내비게이션의 위치·남은 시간, 주행 중 최소 표시(DO), 음성 안내, 정차 중에만 가능한 조작 | 실차 주행 검증은 하지 않았다. 에뮬레이터 시험이라고 밝힌다 |
| 창의성 | 픽업 때 반복되는 "어디야?"·"지금 내려갈까?" 연락 줄이기, 탑승자는 설치·가입 없이 링크 하나 | 연락이 실제로 줄어드는지는 검증하지 않았다. 효과를 입증한 것처럼 쓰지 않는다 |
| 기술 활용성 | NaviHelper(위치·ETA·경유지·도착 이벤트), TextToSpeech | 구현한 기능과 향후 계획을 구분해 표시 |
| 사업성 | 타깃 고객, 사용자 확보와 지속 이용 | **설문·인터뷰 결과가 저장소에 없다.** 문제 근거는 실제 응답으로만 쓴다. 사용성 테스트는 아직 하지 않았다 |

## 시연 영상 다시 찍기

제출 버전 한 흐름으로 녹화한다: 차량에서 픽업 생성 → 운전자 휴대전화로 QR 열기 → 탑승자에게 링크 공유 → 탑승자 참여(이름·승인 없음) → 지도에서 차량 위치와 남은 시간 → 준비 완료가 차량에 표시 → 도착 → 탑승 확인과 공유 종료. 도착 임박 알림과 장소 제안은 시연할 수 있게 되면 넣는다.

- 영상에 쓴 저장소별 커밋을 기록한다.
- 시험용 계정과 장소만 쓴다. 초대 토큰, 실제 개인 위치, 서버 주소 외의 운영 정보가 화면에 나오지 않게 한다.
- 실제 SDK 데이터와 시뮬레이션 데이터를 구분해 자막이나 설명에 적는다.

## 개인정보와 공개 범위

- 동의서는 서명이 필요한 개인정보다. 저장소에 올리지 않고 메일로만 보낸다.
- 공식 안내상 개인정보는 후속 일정이 끝나는 2027-02-28까지 보관 후 파기된다.
- release 서명 키(keystore)와 비밀번호는 저장소에 넣지 않는다.
- 소개 자료에 VM 이름·고정 IP·프로젝트 식별값·운영 자격 증명을 넣지 않는다.
