# 제출 자료 안내

이 저장소는 마중의 서비스 설명과 시연을 모아두는 입구입니다.
GitHub 링크만으로 공모전 제출이 완료되는 것은 아닙니다. 기획서·제출 방식·열람 권한은 실제 제출 시점의 공식 안내에 맞춰 확인해야 합니다.

## 처음 보는 사람이 확인할 순서

1. [README](../README.md): 누구를 위한 서비스인지, 사용 흐름과 현재 구현 범위 확인.
2. [시연 영상](pickup-demo.md): 차량 앱과 탑승자 웹을 연결한 기본 픽업 흐름 확인.
3. [시연 조건](pickup-demo.md): 실제 SDK·로컬 API 시험과 실차 주행의 차이 확인.
4. [개발 저장소](../README.md#개발-저장소): 코드·실행 방법·개별 시험 결과 확인.

현재 영상에는 링크 복사·이름 입력·운전자 승인이 나옵니다. 목표인 QR 공유·이름 없는 자동 연결을 구현한 영상으로 설명하지 않습니다.
차량 재실행 복구와 화면 밖 전송은 이후 개발한 기능이므로 각 PR의 검증 기록을 함께 봅니다.

## 자료별 관리 위치

| 자료 | 위치·현재 상태 |
| --- | --- |
| 서비스 소개·사용 흐름·전체 구조 | 이 저장소 README |
| 기존 통합 시연 영상·캡처 | `docs/media/`, 당시 촬영 범위 표기 |
| API·실행·빌드·시험 방법 | 차량·웹·백엔드 저장소 |
| 기능별 계획·역할 | `docs/revised-plan.md`와 팀 노션 |
| 최종 제출 기획서 | 이 저장소에 최종본을 아직 지정하지 않음 |
| 최종 시연·설치 파일 | 제출할 버전과 일치하는 자료를 별도로 확정해야 함 |

## 제출 전에 마무리할 것

- QR 공유·참여·준비 상태·도착·완료를 제출 버전에서 한 흐름으로 다시 확인하고 녹화합니다.
- 영상에 사용한 코드 버전과 실행 환경을 기록합니다. 저장소별 커밋 또는 release tag를 함께 적어 코드를 바꾼 뒤 옛 영상만 남는 일을 줄입니다.
- 차량 앱 설치 파일을 제공한다면 사용 가능한 에뮬레이터·설치 순서·서버 연결 조건을 함께 적습니다. 공개 서버가 준비되지 않았다면 바로 접속 가능한 서비스로 소개하지 않습니다.
- 저장소가 비공개라면 심사 측이 실제로 읽을 수 있는 접근 방식과 영상·문서 열람 권한을 확인합니다. 이 문서 작업에서 공개 범위를 변경하지 않습니다.
- 기획서·동의서·팀 정보·파일명·접수 방법은 공식 제출 안내와 대조합니다. 아직 확인하지 않은 자료를 ‘제출 완료’로 표시하지 않습니다.

VM 이름·고정 IP·프로젝트 식별값·운영 자격 증명은 소개 자료에 넣지 않습니다.
시연에는 시험용 계정·장소를 사용하고, 초대 토큰이나 실제 개인 위치가 화면에 노출되지 않도록 확인합니다.
