
# 두 사람이 함께 테스트하기

마중의 주요 기능을 운전자와 탑승자 입장에서 확인하는 테스트 가이드다.

차량용 마중 앱과 모바일 웹을 연결하여 픽업 요청부터 탑승 완료까지의 흐름을 점검한다.

> 이 문서는 테스트 절차를 안내한다. 아래 항목이 모두 검증 완료됐다는 뜻은 아니다. 실제 테스트 결과는 별도로 기록한다.

---

## 1. 테스트 환경 준비

### 필요한 환경

| 구분 | 준비 사항 |
| --- | --- |
| 운전자 | 카카오 계정 1개 |
| 탑승자 | 운전자와 다른 카카오 계정 1개 |
| 차량 | Pleos Connect 공식 에뮬레이터 1대 |
| 휴대전화 | 모바일 웹 접속이 가능한 실제 휴대전화 |
| 차량 앱 | 마중 서버 주소로 빌드된 서명 APK |
| 서버 | 마중 HTTPS 시험 대상 서버 |

운전자와 탑승자는 서로 다른 계정을 사용한다.

차량 앱은 공식 Pleos 에뮬레이터에서 실행하고, 탑승자는 휴대전화 웹브라우저에서 마중에 접속한다.

실제 집이나 직장 주소 대신 테스트용 장소를 사용하는 것을 권장한다.

### 테스트 전 확인

**① 서버 상태**

https://majung.cloud/api/v1/health

서버 상태가 `UP`으로 표시되는지 확인한다.

**② 웹 배포 버전**

https://majung.cloud/release.json

현재 배포된 웹 버전을 확인하기 위한 주소다. 일반 사용자가 매번 확인할 필요는 없다.

**③ 차량 앱**

[차량 앱 Releases](https://github.com/majung-team/majung-vehicle-app/releases)

마중 HTTPS 서버 주소로 빌드한 APK를 설치한다.

**④ 차량 계정 연결**

최초 등록 및 운전자 계정 연결을 완료한 상태에서 테스트한다.

아직 연결하지 않았다면 [차량 앱 설치와 처음 설정](https://github.com/majung-team/majung/wiki/차량-앱-설치)을 먼저 확인한다.

## 2. 기본 픽업 흐름 테스트

운전자와 탑승자가 각각 다음 순서로 진행한다.

| 순서 | 운전자 (차량 앱) | 탑승자 (모바일 웹) |
| --- | --- | --- |
| 1 | 내비게이션에서 시험 경로 설정 및 안내 시작 | 웹 접속 및 카카오 로그인 |
| 2 | 닉네임과 마중 ID 전달 | 사람 찾기에서 운전자 검색 |
| 3 | 받은 요청 화면에서 요청 확인 | 픽업 장소 검색 후 마중 요청 |
| 4 | 요청 수락 및 내비게이션 경로 확인 후 픽업 시작 | 대기 상태에서 진행 중으로 변경되는지 확인 |
| 5 | 위치 공유 권한 허용 및 SDK 정보 전송 확인 | 지도에 차량 위치와 내 장소까지의 ETA 표시 확인 |
| 6 | 탑승자의 준비 완료 상태 확인 | 준비 완료 선택 및 차량 수신 표시 확인 |
| 7 | 정차 후 제안 장소의 경로 확인 및 확정 | 다른 장소 제안 후 확정 전후 표시 비교 |
| 8 | 도착 후 실제 탑승 확인 및 픽업 완료 | 완료 후 차량 위치 공유 종료 확인 |

### 확인할 내용

- 운전자 검색 및 픽업 요청이 정상적으로 동작하는지
- 운전자의 수락과 실제 픽업 시작 상태가 구분되는지
- 픽업 시작 이후 권한이 있는 탑승자에게만 차량 위치가 표시되는지
- 차량 SDK의 ETA가 웹에 반영되는지
- 준비 상태 변경이 차량에 전달되는지
- 장소 변경 제안이 운전자 확정 전까지 적용되지 않는지
- 픽업 완료 후 차량 위치 공유가 종료되는지

## 3. QR 초대 테스트

처음 연결하는 탑승자는 QR 초대 방식으로 참여할 수 있다.

### 테스트 순서

1. 차량 앱에서 픽업 장소 확인
2. QR 기반 초대 생성
3. 운전자 휴대전화로 차량 QR코드 열기
4. 휴대전화 공유 화면에서 탑승자에게 초대 링크 전달
5. 탑승자가 전달받은 링크 열기
6. 픽업 참여
7. 픽업 시작 후 차량 위치 및 ETA 확인

### 재접속 및 참여 복구

같은 브라우저 탭에서 뒤로 이동한 뒤 초대 링크를 다시 열어본다.

기존 참여 정보가 유효하다면 새로운 픽업에 중복 참여하지 않고 기존 참여 상태로 돌아와야 한다.

다음 상황에서는 기존 참여를 복구하지 않아야 한다.

- 이미 취소된 픽업
- 종료된 픽업
- 참여 권한이 해제된 탑승자

브라우저 탭을 완전히 종료하거나 저장 정보를 삭제한 경우는 별도의 테스트 상황으로 구분한다.

## 4. 여러 픽업 요청 테스트

다중 요청과 대기열을 확인하려면 운전자 1명과 탑승자 2명이 필요하다.

**최소 3개의 서로 다른 계정으로 테스트한다.**

### 테스트 순서

1. 첫 번째 탑승자가 픽업 요청
2. 두 번째 탑승자가 별도의 픽업 요청
3. 운전자가 두 요청 확인
4. 첫 번째 픽업 시작
5. 두 번째 탑승자의 대기 상태 확인
6. 첫 번째 픽업 완료
7. 다음 픽업 장소 및 경로 확인
8. 두 번째 픽업 시작

### 확인할 내용

- 여러 요청이 정상적으로 대기열에 등록되는지
- 첫 번째 픽업이 끝나기 전에 두 번째 픽업이 시작되지 않는지
- 대기자에게 다른 픽업의 차량 위치가 공개되지 않는지
- 앞선 픽업 장소까지의 남은 시간이 내 ETA처럼 표시되지 않는지
- 첫 번째 픽업 종료 후 두 번째 요청을 정상적으로 진행할 수 있는지

## 5. 연결 중단 및 복구 테스트

차량과 모바일 웹의 네트워크 연결이 일시적으로 끊어지는 상황을 확인한다.

### 모바일 웹 재접속

1. 픽업 진행 중 모바일 웹 확인
2. 다른 앱이나 화면으로 전환
3. 일정 시간 후 다시 마중 웹으로 복귀
4. 최신 픽업 상태 재조회 확인

이전 화면에 머물지 않고 서버의 최신 상태가 반영되는지 확인한다.

### 차량 연결 중단

1. 픽업 진행 중 차량 연결 중단 상황 재현
2. 모바일 웹의 차량 위치 및 ETA 확인
3. 마지막 정보 표시 여부 확인
4. 정보 유효 시간 만료 후 표시 변화 확인
5. 연결 복구 후 최신 상태 반영 여부 확인

오래된 위치나 예상 도착 시간이 계속 최신 정보처럼 표시되면 안 된다.

연결 복구 시에는 서버 상태와 픽업 권한을 다시 확인해야 한다.

## 6. 도착 알림 테스트

마중은 도착 예정 시간에 따라 알림을 제공하는 기능을 포함한다.

도착 약 3분 전 알림을 확인하려면 브라우저 알림 권한과 지원 환경이 필요하다.

### 테스트 준비

- 알림 권한 허용
- 푸시 알림을 지원하는 브라우저 및 운영체제 확인
- iPhone의 경우 홈 화면에 추가한 웹 앱에서 시험
- 테스트용 픽업 및 ETA 정보 준비

### 확인할 내용

1. 알림 권한 요청 및 허용 동작
2. 도착 약 3분 전 알림 발생 여부
3. 알림 배너 표시 여부
4. 알림 선택 시 해당 픽업으로 이동하는지
5. 브라우저를 벗어난 상태에서 수신되는지
6. LTE 및 Wi-Fi 전환 후 알림 동작

> **검증 범위 주의**
>
> 공식 에뮬레이터에서 기능을 확인한 것만으로 실제 휴대전화의 푸시 알림까지 검증했다고 판단하지 않는다.
>
> 실제 기기, 브라우저 및 네트워크 환경별 결과를 별도로 기록한다.

## 7. 테스트 결과 기록

테스트를 수행했다면 성공 여부와 재현 조건을 함께 기록한다.

| 항목 | 기록 내용 |
| --- | --- |
| 테스트 일시 | 수행 날짜 및 시간 |
| 테스트 환경 | 에뮬레이터, 휴대전화, 브라우저 |
| 차량 앱 버전 | 설치한 APK 버전 |
| 웹 버전 | release.json 기준 |
| 테스트 기능 | 픽업 요청, 초대, ETA, 준비 상태 등 |
| 결과 | 성공 / 실패 / 미실행 |
| 문제 상황 | 발생 화면과 직전 동작 |
| 관련 자료 | 화면 캡처, 로그, GitHub 이슈 |

### 문제 발생 시

다음 내용을 기록하면 문제를 재현하고 원인을 확인하는 데 도움이 된다.

- 문제가 발생한 화면
- 발생 날짜 및 시간
- 직전에 선택한 버튼이나 동작
- 서버 health 상태
- 웹 및 차량 앱 버전
- 오류 메시지 또는 관련 로그

개인정보 보호를 위해 실제 위치 정보, 계정 인증 토큰, 초대 링크의 비밀 값 등은 공개 기록에 포함하지 않는다.

## 8. 현재 검증 범위

2026년 10월 30일 기준으로 다음과 같이 구분한다.

**확인된 범위**

- 단위 테스트 및 시험 서버 기반 기능 검증
- 공식 Pleos 에뮬레이터와 SDK를 이용한 주요 기능 확인
- 실제 iPhone Chrome에서 로그인, 탭 이동, 검색 및 재접속 확인
- 모바일 웹 일부 사용성 문제 개선

**추가 검증이 필요한 범위**

- 실제 휴대전화와 차량 에뮬레이터를 연결한 전체 픽업 흐름
- 도착 알림 배너 수신 및 알림 이동
- LTE 및 Wi-Fi 전환 상황
- 브라우저별 동작 차이
- 실제 차량 환경에서의 동작

테스트 절차와 실제 완료된 검증은 구분해서 기록한다.
