# 두 사람이 함께 테스트하기

운전자 한 명과 탑승자 한 명이 서로 다른 카카오 계정을 쓴다. 차량은 공식 Pleos 에뮬레이터 한 대, 탑승자는 실제 휴대전화를 준비한다.

## 먼저 확인

- https://majung.cloud/api/v1/health 에서 `UP`이 보이는지 확인한다.
- https://majung.cloud/release.json 은 현재 웹 버전 확인용이다. 사용자가 매번 열 필요는 없다.
- 차량 APK는 마중 HTTPS 주소로 빌드한 버전을 설치한다.
- 차량 최초 등록과 운전자 계정 연결을 끝낸다.
- 집이나 직장 대신 시험용 장소를 사용한다.

## 기본 흐름

| 순서 | 운전자 | 탑승자 |
| --- | --- | --- |
| 1 | 내비에서 시험 경로를 안내한다 | 웹에 로그인한다 |
| 2 | 닉네임·마중 ID를 알려준다 | 사람 찾기에서 운전자를 찾는다 |
| 3 | 차량의 받은 요청을 확인한다 | 장소를 검색하고 마중을 요청한다 |
| 4 | 요청을 수락한다. 내비에서 요청 장소를 확인한 뒤 픽업을 시작한다 | 대기에서 진행 중으로 바뀌는지 확인한다 |
| 5 | 위치 공유 권한을 허용한다 | 지도·내 도착 시간이 표시되는지 확인한다 |
| 6 | 준비 완료 표시를 확인한다 | 준비 완료를 누르고 차량 수신 표시를 확인한다 |
| 7 | 정차 후 제안 장소의 경로를 확인하고 확정한다 | 다른 장소를 제안하고 확정 전후 표시를 비교한다 |
| 8 | 도착 후 탑승을 확인하고 완료한다 | 완료 뒤 차량 위치가 사라지는지 확인한다 |

QR 초대도 한 번 별도로 시험한다. 차량 QR → 운전자 휴대전화의 공유 화면 → 탑승자에게 링크 전달 → 탑승자 참여 순서다.

여러 탑승자의 대기 순서는 서로 다른 탑승자 계정 두 개가 필요하다. 운전자 포함 최소 세 계정으로 두 요청을 받고, 첫 픽업이 끝나기 전에 두 번째 픽업이 시작되지 않는지 확인한다.

## 연결과 알림

웹을 잠시 다른 화면으로 전환했다가 돌아와도 최신 상태를 다시 읽어야 한다. 차량 연결이 끊겼을 때 지난 위치가 계속 새 위치처럼 보이면 안 된다.

도착 3분 전 알림은 브라우저 알림 권한이 필요하다. iPhone은 홈 화면에 추가한 웹 앱에서 시험한다. 알림 배너 수신·LTE 전환·브라우저별 동작은 실제 휴대전화에서 확인하고 결과를 따로 적는다. 에뮬레이터 시험만으로 이 항목을 통과했다고 적지 않는다.

문제가 생기면 주소의 토큰이나 실제 위치 대신, 화면·발생 시각·직전에 누른 버튼·health와 웹 버전을 남긴다.
